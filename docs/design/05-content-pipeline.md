# 05 — Content Pipeline

This document is the owner's operating manual for generating, reviewing, and publishing all card content in Chaos Creatures. Everything here is designed to run with a single command or a single click. No engineering judgment required.

**Depends on:** `00-game-design-master.md`, `01-battle-mechanics.md` (stat ranges, PP system, factions), `02-card-data-model.md` (CardTemplate schema), `03-prompt-templates.md` (FLUX and GPT-4o Mini prompt details)

**Infrastructure stack:** fal.ai (image generation), OpenAI API (text generation), Supabase (database), Cloudflare R2 (art storage + CDN), Railway (batch job runner)

### 1b. Per-Card Requirements

Every card template needs all six of the following before it can be inserted into Supabase:

1. **Base art** — 1024x1024 PNG generated by fal.ai FLUX Dev (txt2img), stored in Cloudflare R2
2. **Card name** — 2-4 words, faction-appropriate, generated by GPT-4o Mini
3. **Flavor text** — 1-2 sentences under 140 characters, generated by GPT-4o Mini
4. **Stat assignment** — ATK, HP, CM cost (1-6), base instability (0-5), keywords (0-1 at Common), all within PP budget
5. **Card type and effect** — CREATURE, SPELL, or STABILIZER; spells and stabilizers have a structured effect definition
6. **Balance validation** — automated PP check, stat range check, instability coherence check all passing

## 2. The Generation Pipeline — End to End

### 2a. How It Works (One-Sentence Summary)

The owner runs one command in a terminal. The system generates all card art and text, validates everything automatically, and opens a review gallery in a browser. The owner clicks Approve or Reject on each card. Approved cards are inserted into Supabase. Rejected cards are regenerated with one click.

### 2b. Pipeline Architecture

```
[owner runs: npm run generate-batch --faction=ironwright --count=50]
         |
         v
[scripts/generate-batch.ts]
  - reads card-specs/ironwright.csv
  - for each card in batch:
      POST to fal.ai FLUX Dev --> get image URL
      POST to OpenAI GPT-4o Mini --> get name + flavor_text
      run automated QA checks
      write result to batch_results/run_TIMESTAMP.json
  - opens review gallery at http://localhost:3001
         |
         v
[Review Gallery — http://localhost:3001]
  - displays all generated cards in a grid
  - owner clicks Approve / Reject (Art) / Reject (Name) / Edit
  - approved cards: uploaded to Cloudflare R2 --> inserted into Supabase
  - rejected cards: queued for regeneration (one click per card)
         |
         v
[Supabase card_templates table]
  - card is now live in the database
  - players can acquire this card from packs
```

### 2c. Prerequisites — What the Owner Does Once

Before the first batch run, the owner must have these accounts and API keys in `/chaos-creatures/.env`:

```
FAL_API_KEY=...               # from fal.ai dashboard
OPENAI_API_KEY=...            # from platform.openai.com
SUPABASE_URL=...              # from Supabase project settings
SUPABASE_SERVICE_ROLE_KEY=... # from Supabase project settings (not anon key)
CLOUDFLARE_ACCOUNT_ID=...     # from Cloudflare dashboard
CLOUDFLARE_R2_ACCESS_KEY=...  # from Cloudflare R2 API tokens
CLOUDFLARE_R2_SECRET_KEY=...  # from Cloudflare R2 API tokens
CLOUDFLARE_R2_BUCKET=chaos-creatures-card-art
CLOUDFLARE_R2_PUBLIC_URL=https://pub-XXXXXXXX.r2.dev
```

Claude Code builds the scripts. The owner only sets the `.env` values.

## 3. Exact API Calls

### 3a. fal.ai FLUX Dev — Base Card Art Generation

**Endpoint:** `POST https://fal.run/fal-ai/flux/dev`

**Authentication:** `Authorization: Key ${FAL_API_KEY}` header

**Request JSON (example: Ironwright 3-cost creature, instability 2, balanced):**

```json
{
  "prompt": "steampunk mechanical creature, brass and copper materials, exposed gears and clockwork mechanisms, riveted metal plating, steam vents, intricate engineering, industrial aesthetic, clockwork wolf, sleek predator design, glowing amber eyes, mechanical jaw with visible pistons, articulated brass limbs, balanced and symmetrical construction, portrait orientation, centered composition, dramatic lighting from above-left, creature in prowling stance, industrial workshop background with soft focus, fantasy card game art, high detail, professional digital art, sharp focus, vibrant warm metallic tones, Magic: The Gathering style, clean edges, no text, no watermarks",
  "negative_prompt": "text, words, letters, watermarks, signatures, logos, borders, frames, NSFW, explicit content, gore, low quality, blurry, distorted anatomy, multiple heads, deformed limbs, floating objects",
  "image_size": "square_hd",
  "num_inference_steps": 35,
  "guidance_scale": 7.5,
  "num_images": 1,
  "enable_safety_checker": true,
  "output_format": "png"
}
```

**Parameter reference:**

| Parameter | Value | Notes |
|---|---|---|
| `image_size` | `"square_hd"` | Produces 1024x1024 PNG |
| `num_inference_steps` | 35 | Quality vs. speed tradeoff. Use 30 for fast preview runs, 35 for production |
| `guidance_scale` | 7.5 | Higher = more prompt-adherent, less creative |
| `num_images` | 1 | One image per API call |
| `enable_safety_checker` | true | fal.ai built-in NSFW filter — automatically rejects unsafe outputs |
| `output_format` | `"png"` | PNG for lossless quality |

**Response JSON:**

```json
{
  "images": [
    {
      "url": "https://fal.media/files/rabbit/xxxx.png",
      "width": 1024,
      "height": 1024,
      "content_type": "image/png"
    }
  ],
  "timings": {
    "inference": 4.2
  },
  "seed": 1234567890,
  "has_nsfw_concepts": [false],
  "prompt": "steampunk mechanical creature..."
}
```

**What the pipeline does with this response:**
1. Reads `images[0].url` — this is a temporary fal.ai CDN URL (expires in ~1 hour)
2. Downloads the image bytes immediately
3. Runs automated QA checks (Section 4)
4. If QA passes: stores in `batch_results/run_TIMESTAMP/ironwright/card_001.png` locally
5. After owner approval: uploads to Cloudflare R2 at `cards/ironwright/card_001.png`
6. Records the R2 public URL as the permanent `art_url` in Supabase

### 3b. OpenAI GPT-4o Mini — Card Name and Flavor Text

**Endpoint:** `POST https://api.openai.com/v1/chat/completions`

**Authentication:** `Authorization: Bearer ${OPENAI_API_KEY}` header

**Request JSON (example: Ironwright 3-cost, instability 2, ATK 3/HP 4, no keyword):**

```json
{
  "model": "gpt-4o-mini",
  "temperature": 0.8,
  "max_tokens": 150,
  "response_format": { "type": "json_object" },
  "messages": [
    {
      "role": "system",
      "content": "You are a card name and flavor text generator for Chaos Creatures, a fantasy card game. Always respond with valid JSON only."
    },
    {
      "role": "user",
      "content": "Generate a card name and flavor text for this card.\n\nFACTION: The Ironwright Collective\nFACTION VOICE: Industrial, pragmatic, precise. Names use mechanical compound words and references to metals, gears, and steam. Flavor text emphasizes function, craftsmanship, and the fusion of magic and machinery.\nCREATURE ARCHETYPE: clockwork wolf\nSTATS: 3 ATK / 4 HP, 3 chaos mote cost\nINSTABILITY: 2 (balanced)\nKEYWORDS: none\nVISUAL DESCRIPTION: balanced and composed, dynamic neutral stance, moderate steampunk detail\n\nGenerate:\n1. Card name: 2-4 words, faction-appropriate, memorable\n2. Flavor text: 1-2 sentences, under 140 characters, faction voice\n\nRespond ONLY with this JSON:\n{\"name\": \"...\", \"flavor_text\": \"...\"}"
    }
  ]
}
```

**Response JSON:**

```json
{
  "id": "chatcmpl-xxxx",
  "object": "chat.completion",
  "model": "gpt-4o-mini",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "{\"name\": \"Cogfang Stalker\", \"flavor_text\": \"Designed for pursuit, refined through conflict. Its tolerances are tighter than its prey's nerves.\"}"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 186,
    "completion_tokens": 38,
    "total_tokens": 224
  }
}
```

**What the pipeline does with this response:**
1. Parses `choices[0].message.content` as JSON
2. Extracts `name` and `flavor_text`
3. Validates: name is 3-30 characters, flavor text is under 200 characters
4. If validation fails: retries once with a stricter prompt ("The name must be 2-4 words and under 30 characters total. Do not explain, just output JSON.")
5. Stores alongside the card's art result in `batch_results/run_TIMESTAMP.json`

**System prompt by faction (used verbatim in the `system` message):**

```

"Industrial, pragmatic, precise. Names use mechanical compound words and references to metals, gears, and steam. Flavor text emphasizes function, craftsmanship, and the fusion of magic and machinery. Order tone = perfected engineering. Chaos tone = pushed beyond limits."

The Fey Courts system addition:
"Ethereal, ancient, organic. Names use nature terms (Thorn, Root, Bloom, Grove) and fey titles (Warden, Huntress, Speaker). Flavor text is lyrical, timeless, referencing cycles and wildness. Order tone = harmony with nature, eternal patience. Chaos tone = wild hunt, primal fury."

The Demonic Kingdoms system addition:
"Visceral, corrupted, direct. Names use dark materials (Ash, Bone, Blood, Shadow) and violent verbs (Reaver, Ripper, Render). Flavor text is ominous and foreboding. Order tone = controlled fury, dark pacts. Chaos tone = unbound carnage, apocalyptic."
```

**Cost:** GPT-4o Mini charges $0.15 per 1M input tokens and $0.60 per 1M output tokens. At roughly 200 input tokens and 40 output tokens per card: approximately $0.000054 per card, or $0.02 for all 360 faction cards. Text generation cost is effectively negligible.

**Using OpenAI Batch API for launch generation:** For the full 360-card launch run, use the OpenAI Batch API instead of real-time calls. This reduces cost by 50% (already negligible) and removes rate-limit concerns. The batch pipeline script automatically chooses Batch API for runs over 100 cards.

**Batch API request format:** Submit a `.jsonl` file where each line is one request:

```jsonl
{"custom_id": "ironwright-001", "method": "POST", "url": "/v1/chat/completions", "body": {"model": "gpt-4o-mini", "temperature": 0.8, "max_tokens": 150, "response_format": {"type": "json_object"}, "messages": [...]}}
{"custom_id": "ironwright-002", "method": "POST", "url": "/v1/chat/completions", "body": {"model": "gpt-4o-mini", "temperature": 0.8, "max_tokens": 150, "response_format": {"type": "json_object"}, "messages": [...]}}
```

Submit with: `POST https://api.openai.com/v1/batches`

```json
{
  "input_file_id": "file-xxxx",
  "endpoint": "/v1/chat/completions",
  "completion_window": "24h"
}
```

Batch API results arrive within 24 hours. For launch content, text generation can run the night before the art review session.

### 3c. Cloudflare R2 — Art Upload

After the owner approves a card in the review gallery, the pipeline uploads the local PNG to Cloudflare R2 using the AWS S3-compatible API (R2 is S3-compatible).

**Upload call (using AWS SDK v3 with R2 endpoint):**

```typescript
import { S3Client, PutObjectCommand } from "@aws-sdk/client-s3";

const r2 = new S3Client({
  region: "auto",
  endpoint: `https://${process.env.CLOUDFLARE_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  credentials: {
    accessKeyId: process.env.CLOUDFLARE_R2_ACCESS_KEY,
    secretAccessKey: process.env.CLOUDFLARE_R2_SECRET_KEY,
  },
});

const key = `cards/${faction}/${cardId}.png`;

await r2.send(new PutObjectCommand({
  Bucket: process.env.CLOUDFLARE_R2_BUCKET,
  Key: key,
  Body: imageBuffer,
  ContentType: "image/png",
  CacheControl: "public, max-age=31536000, immutable",
}));

const publicUrl = `${process.env.CLOUDFLARE_R2_PUBLIC_URL}/${key}`;
// e.g. https://pub-XXXXXXXX.r2.dev/cards/ironwright/abc123.png
```

The `publicUrl` is stored as `art_url` in the Supabase `card_templates` table. The `Cache-Control: immutable` header means Cloudflare CDN never re-fetches this image — it is cached globally forever, since base card art never changes.

### 3d. Supabase — Card Template Insert

After R2 upload, the pipeline inserts the approved card into Supabase using the service role key (bypasses Row Level Security for admin writes).

**Insert call:**

```typescript
import { createClient } from "@supabase/supabase-js";

const supabase = createClient(
  process.env.SUPABASE_URL,
  process.env.SUPABASE_SERVICE_ROLE_KEY
);

const { data, error } = await supabase
  .from("card_templates")
  .insert({
    id: crypto.randomUUID(),
    name: "Cogfang Stalker",
    faction_id: "ironwright",
    card_type: "CREATURE",
    cm_cost: 3,
    base_instability: 2,
    base_attack: 3,
    base_health: 4,
    base_keywords: [],
    spell_effect: null,
    stabilizer_type: null,
    art_url: "https://pub-XXXXXXXX.r2.dev/cards/ironwright/abc123.png",
    art_prompt: "steampunk mechanical creature...(full prompt stored here)",
    flavor_text: "Designed for pursuit, refined through conflict. Its tolerances are tighter than its prey's nerves.",
    batch_id: "batch_2026_02_launch_ironwright_001",
    approved_at: new Date().toISOString(),
    approved_by: "owner"
  });

if (error) {
  console.error("Insert failed:", error.message);
  // Pipeline logs this and continues with next card
  // Failed inserts are shown in a "retry" section of the review gallery
}
```

**The Supabase `card_templates` table schema** (Claude Code creates this migration):

```sql
create table card_templates (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  faction_id text not null references factions(id),
  card_type text not null check (card_type in ('CREATURE', 'SPELL', 'STABILIZER')),
  cm_cost integer not null check (cm_cost between 1 and 6),
  base_instability integer check (base_instability between 0 and 5),
  base_attack integer check (base_attack >= 0),
  base_health integer check (base_health >= 1),
  base_keywords text[] not null default '{}',
  spell_effect jsonb,
  stabilizer_type jsonb,
  art_url text not null,
  art_prompt text not null,
  flavor_text text not null,
  batch_id text,
  approved_at timestamptz not null default now(),
  approved_by text not null default 'owner',
  is_available boolean not null default true,
  created_at timestamptz not null default now()
);

create index idx_card_templates_faction on card_templates(faction_id);
create index idx_card_templates_available on card_templates(is_available);
```

## 4. Automated Quality Checks

These run automatically during batch generation, before any card reaches the review gallery. Checks that fail trigger automatic regeneration (up to 2 retries), then flag the card for the owner to manually reject or keep.

### 4a. Art Quality Checks

Run immediately after receiving the fal.ai response, before downloading the image:

| Check | Rule | On Failure |
|---|---|---|
| NSFW flag | `has_nsfw_concepts[0]` must be `false` in fal.ai response | Auto-regenerate with same prompt. After 2 failures: flag as NSFW_REJECTED in gallery |
| Image URL present | `images[0].url` must be a valid URL | Auto-retry API call |

Run after downloading the image:

| Check | Rule | On Failure |
|---|---|---|
| Resolution | Image must be 1024x1024 pixels exactly | Auto-regenerate |
| File size | 100KB–4MB | Below 100KB = likely corrupted, regenerate. Above 4MB = unexpected, log and regenerate |
| Not blank | Less than 95% of pixels the same color | Auto-regenerate (blank = generation failure) |

The pipeline uses the `sharp` Node.js library for image checks. Sharp is installed as a project dependency by Claude Code.

### 4b. Text Quality Checks

Run immediately after receiving the OpenAI response:

| Check | Rule | On Failure |
|---|---|---|
| Valid JSON | Response parses as `{name, flavor_text}` | Retry once with explicit JSON instruction |
| Name length | 3-30 characters | Retry with "Name must be 2-4 words, under 30 characters total" added to prompt |
| Name not generic | Not "Creature", "Card", "Unit", "Monster" | Retry |
| Flavor text length | Under 200 characters | Retry with "Flavor text must be under 140 characters" added to prompt |

### 4c. Balance Checks

Run after stat assignment from the card spec CSV (before generation), and again after generation to confirm stats were recorded correctly:

```
PP budget check:
  required: (base_attack + base_health + keyword_pp_cost) == (cm_cost * 2 + 1)
  tolerance: ±1 PP allowed
  keyword PP costs: Shield=3, Lifesteal=2, Flying=2, Reach=1, Deathtouch=3, Taunt=1, Piercing=2

Stat range check (from 01-battle-mechanics.md Section 12):
  CM 1: ATK 1-2, HP 1-2
  CM 2: ATK 1-3, HP 2-4
  CM 3: ATK 2-4, HP 2-5
  CM 4: ATK 2-5, HP 3-6
  CM 5: ATK 3-6, HP 3-7
  CM 6: ATK 4-7, HP 4-8

Instability coherence check:
  instability 0-1: HP must be >= ATK
  instability 2: HP within 1 of ATK (either direction)
  instability 4-5: ATK must be >= HP

Deathtouch constraint:
  if keyword includes Deathtouch: ATK must be <= 2

Zero stat check:
  ATK must be >= 1
  HP must be >= 1

Common keyword limit:
  max 1 keyword at Common tier
```

Cards that fail balance checks are NOT auto-regenerated (art is fine, the spec has a bug). They are flagged in the review gallery with a red "BALANCE FAIL" badge showing the specific rule that failed. The owner can edit the stats directly in the gallery UI and revalidate.

### 4d. What the Owner Sees in the Gallery

Every card in the gallery has one of these status badges:

- **READY** (green) — all checks passed, click Approve to publish
- **BALANCE FAIL** (red) — stat math is wrong, shows which check failed, owner edits stats inline
- **ART REGEN** (yellow) — art failed checks and was auto-regenerated, shows attempt count
- **TEXT REGEN** (yellow) — name or flavor text was auto-regenerated
- **NSFW REJECTED** (red) — failed NSFW check 2 times, owner must manually reject and the pipeline skips it

## 5. Review Gallery UI

### 5a. Accessing the Gallery

After running the batch generation command, the gallery starts automatically at `http://localhost:3001`. Claude Code builds this as a standalone Node.js Express server that the owner launches via the same `npm run generate-batch` command. The gallery persists between sessions — closing the terminal and re-opening it shows the same batch in progress.

To view a previous batch: `npm run review-gallery --batch=batch_2026_02_launch_ironwright_001`

### 5b. Gallery Layout

The gallery is a single HTML page (server-rendered, no framework needed). Claude Code builds this as a standalone Express + plain-HTML page with minimal JavaScript.

**Header bar:**
- Batch name and date
- Progress counters: `Approved: 23 / Pending: 19 / Rejected: 8 / Total: 50`
- "Publish All Approved" button (green) — inserts all approved cards into Supabase at once
- "Regenerate All Rejected" button (yellow) — queues all rejected cards for regeneration

**Card grid:**
- 4 columns on desktop, 2 on mobile
- Each card cell shows:
  - Art image (1024x1024, displayed at 256x256)
  - Status badge (READY / BALANCE FAIL / etc.)
  - Card name (large, editable inline)
  - Faction + type + CM cost
  - Stats: `ATK X / HP Y / Instability Z`
  - Keywords (if any)
  - Flavor text (editable inline, small text below stats)
  - PP budget display: `PP used: X / PP budget: Y` (green if ±1, red if over)
  - Three action buttons:
    - **Approve** (green) — marks card ready to publish
    - **Reject Art** (red) — discards art, queues art regeneration
    - **Reject All** (red) — discards entire card, queues full regeneration

**Card detail modal (click any card art to expand):**
- Full-size art (1024x1024)
- All card data
- Full edit form for stats, name, flavor text
- "Revalidate" button after editing
- Art prompt (collapsed by default, expandable for debugging)

**Bottom bar:**
- "Publish All Approved" button (duplicate of header)
- Cost summary: `Total API spend this batch: ~$X.XX`

### 5c. Actions and What They Do

**Approve:**
1. Marks card with `status: 'approved'` in the local batch results JSON
2. Card turns green in the grid
3. Nothing is written to Supabase yet — "Publish All Approved" does that as a batch

**Reject Art:**
1. Marks art as rejected in local JSON
2. Queues a new fal.ai API call with the same prompt but a different seed
3. New art appears in the card cell within 30-60 seconds
4. Card returns to READY status if new art passes checks

## 7. Card Spec CSV Format

The batch generator reads card specs from `card-specs/{faction}.csv`. This is the source of truth for what gets generated. The owner fills this out (or Claude Code fills it based on the distribution tables in Section 1c).

### 7a. CSV Column Definitions

```csv
id,faction_id,card_type,cm_cost,base_instability,base_attack,base_health,keywords,creature_archetype,spell_effect_type,spell_effect_value,spell_effect_target,stabilizer_effect
```

| Column | Type | Required | Description |
|---|---|---|---|
| `id` | string | yes | Unique ID for this card spec. e.g. `ironwright-001`. Used as filename prefix for art. |
| `faction_id` | string | yes | `ironwright`, `fey`, or `demonic` |
| `card_type` | string | yes | `CREATURE`, `SPELL`, or `STABILIZER` |
| `cm_cost` | integer 1-6 | yes | Chaos mote cost |
| `base_instability` | integer 0-5 | creatures only | Instability value. Leave blank for spells/stabilizers. |
| `base_attack` | integer | creatures only | ATK stat. Leave blank for spells/stabilizers. |
| `base_health` | integer | creatures only | HP stat |
| `keywords` | string | no | Pipe-separated keywords. e.g. `Shield` or `Flying|Reach` or empty |
| `creature_archetype` | string | creatures only | Short description for prompt. e.g. `clockwork wolf`, `mycelial guardian`, `infernal ravager` |
| `spell_effect_type` | string | spells only | `DEAL_DAMAGE`, `BUFF_ATK`, `BUFF_HP`, `HEAL`, `DRAW_CARD`, `DESTROY_CREATURE` |
| `spell_effect_value` | integer | spells only | Numeric value of effect (damage amount, buff amount, etc.) |
| `spell_effect_target` | string | spells only | `ANY_CREATURE`, `ENEMY_CREATURE`, `FRIENDLY_CREATURE`, `ENEMY_AVATAR`, `OWN_AVATAR` |
| `stabilizer_effect` | string | stabilizers only | Free-text description of aura effect |

### 7b. Example CSV Rows

```csv
ironwright-001,ironwright,CREATURE,3,2,3,4,,clockwork wolf,,,
ironwright-002,ironwright,CREATURE,1,3,2,1,Piercing,steam-driven dart,,,
ironwright-003,ironwright,CREATURE,4,1,2,6,Shield,armored war golem,,,
ironwright-004,ironwright,SPELL,2,,,,,DEAL_DAMAGE,3,ENEMY_CREATURE,
ironwright-005,ironwright,STABILIZER,3,,,,2 hp,,,,While on field: each of your creatures contributes -1 instability (minimum 0)
```

**PP budget check on ironwright-001:** ATK 3 + HP 4 + keywords 0 = 7 PP. CM cost 3 → budget = (3×2)+1 = 7. Passes.

**PP budget check on ironwright-002:** ATK 2 + HP 1 + Piercing (2 PP) = 5 PP. CM cost 1 → budget = (1×2)+1 = 3. FAILS. This spec is wrong — the pipeline catches this during the pre-generation validation pass and shows it in the dry-run report.

**PP budget check on ironwright-003:** ATK 2 + HP 6 + Shield (3 PP) = 11 PP. CM cost 4 → budget = (4×2)+1 = 9. FAILS by 2 PP. Needs adjustment to ATK 2 + HP 4 + Shield (3 PP) = 9 PP.

The pipeline validates all specs before making any API calls. It outputs a validation report listing all PP failures, stat-range failures, and instability-coherence failures. The owner fixes the CSV and re-runs.

## 8. Full Launch Generation Plan

### 8a. Prerequisite Steps (Owner Does These Once)

1. Create accounts and set API keys in `.env` (see Section 2c)
2. Run `npm install` in the project root (Claude Code does this, no action needed)
3. Run `supabase db push` to apply the `card_templates` table migration (one command)
4. Create the R2 bucket `chaos-creatures-card-art` in the Cloudflare dashboard (30 seconds)
5. Enable public access on the R2 bucket (Settings → Public Access → Allow)
6. Review the starter spec CSVs in `card-specs/` and make any archetype adjustments

### 8b. Step-by-Step Generation Sequence

The full launch run is 8 batches of 50 cards each (4 batches per major faction × 3 factions = 12, but batches of 50 produce ~50 approved cards after rejections). Run one batch at a time. Each batch takes about 30 minutes to generate and 30-60 minutes to review.

**Day 1 — Ironwright Collective:**

```bash
# Batch 1: Ironwright creatures, rows 1-50
npm run generate-batch -- --faction=ironwright --type=creature --count=50 --offset=0

# Review gallery opens automatically. Approve/reject cards.
# Click "Publish All Approved" when done.

# Batch 2: Ironwright creatures, rows 51-100
npm run generate-batch -- --faction=ironwright --type=creature --count=50 --offset=50

# Review and publish.

# Batch 3: Ironwright spells (17) + stabilizers (7) = 24 cards
npm run generate-batch -- --faction=ironwright --type=spell --count=17
npm run generate-batch -- --faction=ironwright --type=stabilizer --count=7
# (These can be combined into one batch: the pipeline handles both types)

# Review and publish.
```

**Day 2 — The Fey Courts:** (same sequence as Day 1, faction=fey)

**Day 3 — The Demonic Kingdoms:** (same sequence as Day 1, faction=demonic)

**Day 4 — Universal Stabilizers (7 cards):**

The 7 universal stabilizer cards from `01-battle-mechanics.md` Section 11 are already fully designed with effects, HP, and CM costs. They need art and text generation only.

```bash
npm run generate-batch -- --faction=universal --type=stabilizer --count=7
```

A `card-specs/universal.csv` file pre-populated with these 7 cards' specs is created by Claude Code.

### 8c. What to Do When You Reject a Card

- **Reject Art** (art looks wrong): Click the button. New art regenerates automatically in ~30 seconds. If the second art is also bad, reject again. After 3 attempts you can force-approve by clicking "Keep Best Attempt" (shows the 3 side by side).
- **Reject Name** (name is generic or wrong): Click the name text, type a new name manually, press Enter. Or click "Regenerate Name" to get a new GPT-4o Mini suggestion.
- **Reject All** (both art and text are wrong): Click "Reject All". Queues full regeneration.
- **Edit Stats** (balance check failed): Click the stat values to edit them. The PP tracker shows in real time if you're within budget. Save when green. No regeneration needed — art and text stay.

### 8d. Expected Approval Rate and Regeneration Budget

Based on AI art generation norms:
- ~75-80% of cards will be approved on first generation
- ~15-20% will need art regeneration (wrong composition, wrong faction feel, artifacts)
- ~3-5% will need text regeneration (generic name, too-long flavor text)
- ~1-2% will be manually stat-edited (PP math error in the spec CSV)

For a 50-card batch: expect to approve ~38-40 immediately, regenerate ~8-10, and manually edit ~1-2. Review time per batch: 30-45 minutes.

### 10c. Balance Patches — Admin UI

Balance patches modify existing `card_templates` records. The owner never edits Supabase directly. Instead, Claude Code builds a simple admin UI at `http://localhost:3002/admin/balance` that:

1. Shows all published cards in a searchable table
2. Owner searches for a card by name
3. Owner edits ATK, HP, instability, or CM cost inline
4. "Validate Change" button runs PP check and stat range check before saving
5. "Save Change" updates the Supabase row
6. A migration script runs automatically after save: updates all `card_instances` that reference this template, recalculating `current_attack`, `current_health`, and `instability_value` based on the new base stats plus each card's existing evolution history

**The migration script (critical — run automatically on every balance patch save):**

```sql
-- After updating card_templates set base_attack = 4 where id = 'ironwright-001'
-- This recalculates all card_instances that reference this template

UPDATE card_instances
SET current_attack = (
  SELECT base_attack FROM card_templates WHERE id = card_instances.template_id
) + COALESCE(evolution_attack_gain, 0) + COALESCE(modifier_attack_gain, 0)
WHERE template_id = 'ironwright-001';
```

The admin UI shows a preview of how many card instances will be affected before the owner confirms the change.

**How balance patches interact with evolved cards:** Template base stat changes propagate. Evolution gains stack on top of the new base. A card that was 3 ATK → evolved to 5 ATK (gained +2) becomes 6 ATK if the template is buffed to 4 ATK base. Modifiers are not recalculated. This is intentional — see `00-game-design-master.md` Key Design Decisions.

## 11. QA and Testing

### 11a. Automated Balance Simulation

After publishing a batch, the pipeline automatically runs a quick balance simulation:

```bash
npm run balance-sim -- --faction=ironwright --games=1000
```

This runs 1,000 simulated games using the production battle engine (the Railway game server) with randomized decks weighted toward newly published cards. It outputs:

- Win rate per card (when drawn)
- Average turns on board per creature
- Average damage dealt per creature
- Cards flagged as outliers (win rate >60% or <30%, or average damage 2× faction median)

**Outlier cards are not automatically changed.** The report is shown to the owner in the admin UI. The owner decides whether to create a balance patch.

**Cost:** $0 (computation only, runs on Railway server)

**Time:** About 5 minutes for 1,000 simulations of the full 360-card pool.

### 11b. Art Quality Gates (Automated)

These run during batch generation (Section 4a). No additional manual step needed.

The pipeline also runs a **faction consistency check** after each batch:

1. Loads all previously approved cards for the faction from Supabase
2. Computes average color histogram for the faction's approved art
3. Compares the new batch's art against the faction average
4. Flags cards whose color histogram deviates more than 40% from the faction median

This catches cards that look like the wrong faction (e.g., a Fey card with fire-orange tones). Flagged cards get a "FACTION STYLE MISMATCH?" warning badge in the gallery — the owner reviews and decides.

### 11c. Regression Testing

Claude Code builds and maintains a test suite at `tests/`. These run automatically:

- On every code commit via GitHub Actions
- Before every `npm run publish-batch` command (blocks publish if any test fails)

**Test categories:**

| Suite | What It Tests | Run Time |
|---|---|---|
| `tests/balance/` | PP budget checks, stat ranges, keyword legality for all card templates in Supabase | ~30 seconds |
| `tests/combat/` | Unit tests for all 7 keyword interactions (all combinations from `01-battle-mechanics.md` Section 4 interaction matrix) | ~10 seconds |
| `tests/instability/` | Player instability calculation formula, clamping rules, evolution instability changes | ~5 seconds |
| `tests/evolution/` | Evolution energy thresholds, shard tier assignments, PP growth calculations | ~5 seconds |
| `tests/deck/` | Deck construction validation (20 cards, single faction, max 2 copies, Legendary limits) | ~5 seconds |
| `tests/events/` | All 16 events (8 Order, 8 Chaos) resolve correctly, trigger sequence order | ~10 seconds |
| **Total** | | **~65 seconds** |

New content (new cards, balance patches) does not require new tests unless a new keyword or mechanic is introduced.

### 11d. Pre-Release Checklist (Run Before Each Quarterly Release)

This is a single command:

```bash
npm run pre-release-check
```

It runs:
1. All regression tests (Section 11c)
2. Balance validation for all card templates (PP check, stat ranges)
3. Distribution check: instability and CM cost percentages within ±5% of targets
4. Duplicate name check: no two cards in the same faction share a name
5. Art URL reachability check: HTTP HEAD request to every `art_url` in Supabase (verifies R2 files exist)
6. Outputs a pass/fail report. All checks must pass before publishing a quarterly release.

## 13. Risks and Mitigations

| Risk | Mitigation |
|---|---|
| fal.ai API rate limits slow batch generation | Pipeline uses 10 concurrent requests max (stays under rate limits). If rate limited, pipeline auto-waits and retries with exponential backoff (1s, 2s, 4s, 8s). |
| fal.ai downtime during a batch run | Batch state is saved to JSON after every card. Resume with `npm run resume-batch` when service is restored. No cards are lost. |
| OpenAI Batch API takes longer than 24 hours | Rare but possible. The batch pipeline checks status every hour. If a batch is still pending after 48 hours, it automatically falls back to real-time API calls for the remaining cards. |
| High AI art rejection rate (>30%) | Strengthen prompts in `card-specs/[faction].csv` creature archetype descriptions. Add more specificity to the archetype field. Cost impact: $0.025 per extra regeneration — not a financial risk. |
| Balance errors in spec CSV | The pre-generation validation pass catches all PP errors before any API calls are made. Fix the CSV and re-run. |
| Duplicate names across factions | The pre-release check (Section 11d) catches duplicates. Within a faction, names must be unique. Cross-faction duplicates are acceptable (different factions can have a card with the same name). |
| Cloudflare R2 upload failure | Pipeline retries 3 times with 5-second delays. If all 3 fail, the card is marked "UPLOAD_FAILED" in the gallery and can be retried individually via the "Retry Upload" button. |

## Appendix B: Balance Validation Checklist

Use this when manually reviewing flagged cards or when editing stats in the gallery UI. The automated pipeline runs all of these, but this is the human-readable version.

**Creature cards:**

- [ ] PP budget: ATK + HP + keyword PP cost == (CM cost × 2 + 1), tolerance ±1
- [ ] ATK and HP within stat range for CM cost (see Section 1c table)
- [ ] Instability 0-1: HP must be >= ATK
- [ ] Instability 2: HP within 1 point of ATK
- [ ] Instability 4-5: ATK must be >= HP
- [ ] Max 1 keyword at Common tier
- [ ] If keyword is Deathtouch: ATK must be 1 or 2
- [ ] ATK >= 1 and HP >= 1

**Spell cards:**

- [ ] Effect power matches CM cost (see spell ranges in Section 1c)
- [ ] Target type is valid for effect type
- [ ] Name is clear and describes the effect

**Stabilizer cards:**

- [ ] Instability modification is reasonable (±1-3 instability per turn, or fixed value between 5-15)
- [ ] HP between 2-5 (must be destroyable)
- [ ] Cannot have ATK (stabilizers don't attack)
